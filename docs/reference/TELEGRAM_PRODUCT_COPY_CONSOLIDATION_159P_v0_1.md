# Telegram Product Copy Consolidation 159P v0.1

`159P - Telegram Product Copy Consolidation v0` unifies customer-facing copy across the Telegram product shell.

## Scope

- keep product area labels consistent;
- use shared approval boundary language;
- clarify that documents are metadata-only and draft-only;
- prefer customer-facing no-action copy over internal stage language.

## Authority

159P is copy consolidation only. It does not add commands, persistence, onboarding state, document storage, connector activation, OAuth generation, token exchange, Calendar reads or writes, Gmail reads or writes, Memory Center mutation, ProposedMemory writes, model calls, tool calls, worker dispatch, scheduler, proactive outbound sends, billing, deployment, push, merge, PR creation, or external writes beyond approved Telegram replies.

## Shared Boundary Copy

Telegram customer surfaces should use the shared approval boundary lines:

- `I do not write Calendar or Gmail.`
- `I do not remember new facts without approval.`
- `I do not take external actions without approval.`
- `Documents are metadata-only and draft-only right now.`
